# Workspaces — acceptance runbook

**Feature:** Workspaces (Decision 106), pieces 1–5, branches `yehia-khalil/workspaces-1-model` …
`yehia-khalil/workspaces-5-crews`. **Walked by:** — · **Date:** — · **Build:** —

The ten checks below are what a test cannot see: the real organisation, real repositories with their own
bases, a live provider account, the look of the home, and what broke latest. Everything else is the machine
half's. Walk them in the shipped bundle (`make app-bundle`, then open `app/Wakil.app`) with your own
organisation; use a project with at least two git repositories whose default branches differ.
Mark each **met**, **not met** (with what you saw), or **skipped** (with why).

## The walk

1. **The home is the organisation's.** Open Wakil. Expect: the context line is ⌂ · organisation only;
   NEEDS YOU first when anything waits; one slab per project; compact cards; nothing selected. Shrink the
   window to its minimum: no text is cut, the composer row wraps whole. Compare with the approved comp.
2. **Start in sets where, nothing else.** In the composer's *in … ▾*, pick another project's production
   environment. Expect: the screen stays on the home; production reads red in the popover and the label.
   Type a question, Return. Expect: the conversation opens in that project's Main, composer focused.
3. **First change from the right base.** Set the project's branch instructions to name a base per repo
   (e.g. "the app from staging, services from main"). Ask an agent for a one-line change in one repo.
   Expect: a thread line "Made a copy of <repo> from `<base>` on `<branch>`" with the ticket key once;
   `git -C <your folder> status` shows your folder untouched.
4. **Main keeps its terminal.** Before step 3's change, open a terminal in Main and run `ls`. After it,
   go back to Main (⇧⌘H, the project's name). Expect: the same terminal, its shell alive and its `ls`
   still there; the workspace's view has its own terminal in the copy. No editor from the copy in Main.
5. **Back home after real work.** ⇧⌘H. Expect: the workspace's card under its project; Main's block lists
   only conversations you typed in, each once, with no "read only"; when the agent asks to push, an amber
   NEEDS YOU row whose action opens the question.
6. **Hand to agent with a conversation already on the ticket.** On that ticket: Hand to agent. Expect:
   **Send to "…"** first — sends the brief as your turn (queued with Cancel while it is busy). Then
   **Start another**: a "… #2" conversation; ask it to change a file. Expect: it branches off with
   "Branched off … at <sha>. '…' has N uncommitted changes in its copy that are not in yours."
7. **Run two workspaces side by side.** In Settings → the project → Running, Detect a recipe (or let its
   drafting conversation propose one; Save). ▶ on two workspaces' cards. Expect: each running line with
   its own port block from 41200, Stop on each works.
8. **Two agents talk.** In two conversations of one ticket (say api and web), ask one to tell the other a
   contract change. Expect: the other wakes and answers; NEEDS YOU says "waiting on you · N messages"
   only when it is you who is waited on.
9. **The right account.** Expect the ACCOUNT line under every conversation started in this walk to be
   this organisation's own provider account, and the turns to appear in that account's usage — never
   another organisation's.
10. **Finished work leaves.** Merge one workspace's PR on GitHub. Expect: within a minute its card
    offers Archive; Archive removes the copy only if clean (else says where it is) and Earlier counts it.

## Residue from Cover (not reachable by a check)

- Colour: production red and the reserved hues on the home and Start in (checks read text, not colour).
- A run's error under its card (no fixture recipe can fail mid-run).
