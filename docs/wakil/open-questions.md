**Status:** living document · **Split out of `north-star.md` §7 on 2026-09-15** · **Owner:** Yehia Khalil

Recorded honestly rather than guessed. The charter carries a one-line index in its §7 —
number, question, what it blocks, status — and links here; this file carries the
reasoning.

**Questions are cited by number** ("open question 13"), so the number is the address and
is permanent. A closed question is struck through and keeps its entry: what was asked,
and what answered it, is worth more than a tidy list.

**The `Blocks` column is a scheduling instrument.** A question blocking a phase that has
shipped is not a harmless leftover — three of those were found on 2026-09-15 and corrected
(questions 6, 8 and 12).

Decision 12's drift concern is answered rather than waived, the same way as above: a resume is a fork under a fresh Wakil-minted id with recorded lineage (`session_record_parent`), so a chain of org switches produces a chain of short, legible sessions, never one long one silently reused (spec §7). | — |

Each of those built first is a pane whose teardown has to be retrofitted to a contract that did not exist when it was written, which is Decision 9's finding in its general form and the exact reason 2c-i was split out and built before the panes that consume it. **2c-iii is the worst case specifically:** a PTY holding a live shell open in org A's project root, at the moment the window becomes org B. | 18 | ~~**How does a job that is not an agent session pick its model?**~~ **CLOSED 2026-10-08 — by role, per organisation, and the leading answer below stands with five rulings.** (1) A job asks for a role, never a model: `summarise` is built first; `embed` is named and not built, because nothing needs it yet. (2) The org names a provider per role in `org.json`, one field per role beside `speechProvider` — e.g. `"summariseProvider": "local-qwen"`. (3) A local provider is `--kind local` plus `--base-url`, spoken to over the OpenAI-compatible chat-completions API that Ollama, LM Studio and llama.cpp all serve, so none of them is assumed. (4) The call lives in Go, beside the other capabilities, so it runs headless (Invariant 10); the app only shows the result. (5) An unreachable provider is reported on screen and is never replaced by a cloud one. **Its first consumer is chosen:** the chat and inbox work (open question 7) ships as two sub-phases built back to back — first Slack and Gmail readable by the agent, as Jira is; then a brief, on request only (Decision 14's one exception to *reactive in v1*), run on the `summarise` role over what the first fetched. The original entry follows, unchanged.  Phase 3's inbox and chat adapters (summarise, triage) and Phase 4's recall index (open question 3) and proactivity will each want a model call that is not a harness session — one-shot text in, text out, or text in, vectors out — and the operator wants a local model (Ollama or LM Studio on this Mac) to carry them, with Claude kept for agent sessions. Raised 2026-10-08. **Leading answer: roles, not tiers, and never a hard-coded model.** Jobs ask for a role (`agent`, `summarise`, `embed`); each organisation maps roles to provider ids, as `Org.DefaultProvider` already does for `agent` and `Org.SpeechProvider` does for speech (Decision 18) — generalised, or extended one field per role. Two new seams beside `AgentHarness`, shaped like `SpeechProvider` and its registry: a one-call **completion** and an **embedder**, with an OpenAI-compatible local implementation first. `Provider` gains `baseURL`, which Decision 16's 2026-09-08 amendment already names. A role whose provider is down says so on screen and never falls back to the cloud silently, so an org whose text must stay local cannot leak by outage. "Lower" and "higher" were rejected as the axis: privacy, not difficulty, is the reason to go local, an embedding is neither, and routing by difficulty needs repo knowledge a cheap model lacks (measured 2026-09-24: Jev's rule-or-relay and skill router both failed). **Checked against shipped code 2026-10-08: additive, not a rework.** `ProviderKindLocal` exists and is validated (`provider.go`), the per-org role pattern exists twice in `org.json`, and every new field is `omitempty`. Not blocking anything until Phase 3's first adapter that calls a model. | — |
