# Keyboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One keymap table in WakilKit drives the menu bar, every chord tooltip, ⌘K's chord column and a new Settings → Keyboard node where the operator rebinds menu commands.

**Architecture:** `WakilKit/Keyboard/` holds the chord type, the command table and the pure `Keymap` (resolve, assign). Overrides live in `~/.wakil/settings.json` under `"keys"`, read and written by two new `wakil-ctx` tools behind two registry actions (`ctx_keyboard`, operator-only `ctx_set_key`). `AppScene` builds its menus from the table and routes every press through one `WindowModel.keyPressed`, which folds today's `browserKey` fall-through rule into data.

**Tech Stack:** Swift 6 / SwiftUI / AppKit (WakilKit, WakilApp), Go (`internal/wakilcore`, `cmd/wakil-ctx`).

**Spec:** `docs/superpowers/specs/2026-10-28-keyboard-design.md`

## Global Constraints

- Chord strings print modifiers in macOS order **⌃⌥⇧⌘**, then the key: `⌃⌘R`, `⇧⌘T`, `⌘↩`, `⌃⇧Tab`.
- Decision 50 refuses: any chord with neither ⌘ nor ⌃ unless its key is F1–F19; the system chords `⌘Q ⌘H ⌥⌘H ⌘M ⌘Tab ⌘` ⌘Space ⌃Space`; the editing chords `⌘C ⌘V ⌘X ⌘Z ⇧⌘Z ⌘A`.
- `settings.json` `"keys"`: command id → chord string; `""` means deliberately no chord; an absent id means the default. Ids this build does not know are kept on disk.
- `ctx_set_key` is `audience: .operatorOnly`. `ctx_keyboard` is `.agentReachable`, `kind: .read`.
- No dialogs anywhere in this feature (Interaction rule 1); a recorded chord saves on the keystroke (rule 2).
- Commit messages carry no `Co-Authored-By` or "Generated with" lines.
- `make test` runs `docs-check` first, and north-star is over its word limit on `main`. Verify with `go test ./...` and `cd app && swift test --filter <Suite>` instead.
- e2e checks are **not** in this plan: the e2e auditor writes them on the Cover rung (`docs/agents/e2e.md`).

## Review Focus

1. **A key pressed while a browser pane is focused but the browser declines** (⌃⌘S with horizontal tabs, ⇧⌘G with no find bar): the anywhere command, else the key passed on, as today. Pinned in Task 4's `testDeclinedPaneCommandFallsThrough`.
2. **Rebinding the anywhere half of a shared chord** (⌘T to New Scratch Tab moved to ⌃⌘T): ⌘T in a browser still opens a tab, and ⌘T in the editor now passes on. Pinned in Task 3's `testMovingTheAnywhereHalfLeavesThePaneHalf`.
3. **A hand-edited `settings.json` with a refused or duplicate chord:** the refused one is ignored with its row's refusal; for duplicates the first in table order wins. Pinned in Task 3's `testStoredRefusedChordFallsBackToDefault` and `testDuplicateStoredChordFirstInTableWins`.
4. **An older build writing editor settings over a newer build's `keys`:** the map survives untouched. Pinned in Task 1's `TestEditorWriteKeepsKeys`.
5. **A non-Latin keyboard layout:** a chord matched by key code still fires. Pinned in Task 2's `testChordFromEventUsesKeyCodeOnNonLatinLayout`.
