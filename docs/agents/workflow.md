# Workflow

How a sub-phase travels from a row in `north-star.md` §8 to a walked acceptance runbook,
and which tool drives each leg. **Five rungs, three tools, two files.**

## End every turn that finished something with this block

**Required, as a slot rather than a reminder:**

```
**Next:** <the one next step>  ·  **Tool:** <skill or command>  ·  **Blocked by:** <thing, or —>
```

Emit it when the turn **finished a unit of work**: a spec written, a plan phase landed, a
suite green, a question answered that unblocks a decision. Do **not** emit it mid-task —
inside a lookup, or between two tool calls of one step.

## The ladder

| Rung | Done when this exists | Next step | Tool |
|---|---|---|---|
| **Design** | `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`, committed on the branch and reviewed by the operator, and, if it touches UI, saying how it meets each `PRODUCT.md` §Interaction Rules rule it could break | Interrogate the design in one session — purpose, constraints, 2–3 approaches, then sections approved one at a time | `superpowers:brainstorming` |
| **Plan** | `docs/superpowers/plans/YYYY-MM-DD-<topic>.md`, on the branch | Decompose the spec into phases of tasks, each demoable, each test-first | `superpowers:writing-plans` |
| **Build** | the plan's tasks checked off, `make test` and `make app-test` green | Work the plan top to bottom | `superpowers:executing-plans`, which calls `superpowers:test-driven-development` per task and ends a phase at `superpowers:requesting-code-review` |
| **Cover** | every action and identifier the branch touched carries a check, `make e2e` green (the checks the diff reaches), `make e2e-new` red against the merge-base | An agent reads the branch, writes the missing checks, proves each red then green, and reports only what it could not cover | The e2e auditor, `docs/agents/e2e.md`; `make e2e-new`, `make e2e`, `make e2e-runbook` |
| **Walk** | `docs/wakil/phase-<sub-phase>-acceptance.md` written, its checks marked and dated, an entry in `phase-log.md` (for an unmerged sub-phase), all on the branch, and `Met` filled in §8. The full suite runs after the merge, in the night run on `main` | The machine half is `make e2e-runbook`'s; write the human half from what Cover could not reach. Then **the operator walks it — never an agent** | `make e2e-runbook E2E_RUNBOOK=<the document>`; prose for the rest |

The spec, plan and runbook exist only until the branch's final delete (below); after it,
git history holds them.

**Probe and Review are tasks, not rungs.** A sub-phase with something to measure gets a
measurement task in its plan, and its findings amend the spec. A plan phase ends at
`superpowers:requesting-code-review`.

**Read the state off artefacts, never off memory.** Until the final delete, the first of
the spec file, the plan file, a green suite that is missing is where the work is. A
drifted conversation, a compacted context or a fresh session recovers the position by
looking.

## Issues are a bug inbox

GitHub Issues are not work units: a defect found in the field is filed; nothing else is.
The spec is a file and the plan is a file. See `docs/agents/issue-tracker.md`.

## Three rules the ladder does not relax

- **A phase is not met until the operator has walked its runbook.** Writing one is not
  walking it. `Met` says *walked* or *accepted*, and the difference is the point of the
  column.
- **Where a spec and the shipped code disagree, the code is what ships.** Say so, and
  correct the spec on the branch — never quietly match it. The correction is a **dated
  amendment section** in the spec file, with the body edited to match it. A probe that
  contradicts the spec is the same move, made before any code exists.
- **A design question reopened mid-build is a dated amendment to the spec file**, not a
  silent plan edit.

## A runbook is ten checks at most

**Ten, chosen for what a test cannot see.** A runbook nobody walks defends nothing; ten
walked checks beat twenty-six unwalked. Choose by asking:

- **What can a test not see?** Anything needing the shipped bundle rather than a test run,
  anything visual, anything about live input. (A bundled app inherits launchd's
  environment, so a shell spawned without being a login shell can't find `kubectl` while
  every unit test passes.)
- **What broke latest?** Defects found in the final days are the least worn in.

A longer document may keep reference material below, but the **walk** is the ten, written
first, at the top.

## A runbook has a machine half and a human half

**The machine half is rendered; nothing writes it by hand.** It lives between two
markers, and `make e2e-runbook E2E_RUNBOOK=<the document>` replaces everything between them
from the run records — which check ran, against which build, exit status, assertion count,
which were seen to fail against the merge-base, and what the coverage gate said. A red run
renders too.

```
<!-- machine-walk: generated by `make e2e-runbook`; everything between these markers is overwritten -->
<!-- /machine-walk -->
```

A runbook without those two lines is **refused** rather than guessed at.

**The human half stays prose, under the ten-check cap.** It holds only what the machine
cannot see: the visual rulings, *did the right real account get used* against a live
provider, and whatever the Cover rung reported as residue.

is allowed — it drives the Design rung.

## Feature documents leave with the feature

Specs, plans and acceptance runbooks live on the feature's branch and nowhere else.

- The branch's last commit deletes them, **after the walk passes**. Git keeps them.
- Before that, each spec decision that still governs the code becomes a short entry in
  `decisions.md`: the call, one line of why, the commit. The operator reviews it in the PR.
- A spec or plan never merges alone. No separate design or plan PRs.
- In a stack, each PR deletes only its own feature's files.
- `make merge-check` fails while any remain. It gates merging, not opening: a PR can open
  before it passes. Run it only on the PR that targets `main` — in a stack, once the
  branches below it have landed.

The parked issues are indexed in `docs/wakil/parked.md`.
